# v0.5.0 Manual Test Guide — Steps 1–4

## Prerequisites
- **Coordinator machine:** Windows Server 2016+ with coordinator.exe v0.5.0
- **Agent machine:** Separate box (or fresh VM) with Windows PowerShell 5.1
- **Network:** Agent can reach coordinator on HTTPS port 443
- Both binaries rebuilt with fresh Vue dashboard (Jun 7 12:58)

## STEP 1: HTTPS on 443 (Coordinator Machine)

### 1a. Initialize coordinator
```powershell
# Create fresh test directory
$test = "C:\ArcVault-v050-verify"
New-Item -ItemType Directory -Force -Path $test | Out-Null

# Copy binaries
Copy-Item .\coordinator.exe $test\
Copy-Item .\agent.exe $test\
cd $test

# Run init
.\coordinator.exe init
# When prompted:
#   Port: [press Enter for 443]
#   Host: [enter your server's LAN IP, e.g., 192.168.1.100]
#   Database path: [press Enter for default]
```

### Verification
```powershell
# Check config was created
Get-Content .\config.json | ConvertFrom-Json | Select-Object host, port, cert_file, key_file

# Expected output:
# host       : 192.168.1.100 (or your IP)
# port       : 443
# cert_file  : C:\ArcVault-v050-verify\cert.pem
# key_file   : C:\ArcVault-v050-verify\key.pem

# Check cert was generated
Get-ChildItem cert.pem, key.pem

# Examine cert details
openssl x509 -in cert.pem -text -noout | grep -A2 "Subject:\|Issuer:\|Subject Alternative"
# Should show:
# - Subject: CN=192.168.1.100 (your host)
# - SANs including: localhost, 127.0.0.1, your hostname, your IP
# - Signature Algorithm: ecdsa-with-SHA256
```

### 1b. Start coordinator (leave running)
```powershell
.\coordinator.exe start
# Logs should show:
# "ArcVault Coordinator listening on :443 (HTTPS)"
```

### 1c. From second PowerShell shell, verify HTTPS
```powershell
# Test port 443 is open
Test-NetConnection 192.168.1.100 -Port 443
# Expected: TcpTestSucceeded : True

# Test port 8080 is NOT open
Test-NetConnection 192.168.1.100 -Port 8080
# Expected: TcpTestSucceeded : False

# Test API over HTTPS
$result = Invoke-RestMethod "https://192.168.1.100/api/update/check" `
  -SkipCertificateCheck
$result.current
# Expected: v0.5.0
```

**✓ STEP 1 PASS** when 443 succeeds, 8080 fails, API returns v0.5.0 over HTTPS.

## If a Failure Occurs

### TLS/Cert Issues
- Error: "bad certificate" on PS 5.1 during download
- **Cause:** SAN mismatch — the `host` from `coordinator init` doesn't match what agent is dialing
- **Fix:** Rerun `coordinator init` with matching host/IP, then `rekey-cert` to regenerate

### Auth Issues
- Error: "401 Unauthorized" on `/downloads/agent.exe`
- **Cause:** Agent token minting or validation broken
- **Fix:** Check `CreateAgentToken` in database, verify token is being used in script

### Service Won't Start
- Service installed but not running, or crashes
- **Check:**
  ```powershell
  Get-Content C:\ArcVault-Agent\logs\arcvault-agent.log | Select-Object -Last 50
  # Look for HTTPS/TLS errors or database connection errors
  ```

### Job Completes But Files Empty
- Destination folder created but no files copied
- **Cause:** Backup job didn't actually run (status ≠ proof)
- **Fix:** Check agent and coordinator logs, verify source/dest paths in job config
