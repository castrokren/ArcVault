## Step 1 — HTTPS serving on 443, nothing on 8080  *(plan task C3)*
Fresh init in a throwaway dir so you're testing the real `init`→`start` path:
```powershell
$test = "C:\ArcVault-v050-verify"
New-Item -ItemType Directory -Force -Path $test | Out-Null
Copy-Item installer\windows\coordinator.exe $test\
Copy-Item installer\windows\agent.exe       $test\

.\coordinator.exe init          # enter host (e.g. the box's LAN IP) when prompted
```
- [ ] `cert.pem`, `key.pem`, `config.json` created; `config.json` shows `"host"` set and `"port": 443`.

```powershell
.\coordinator.exe start         # leave running; open a SECOND shell for the checks below
```
In the second shell (substitute your host):
```powershell
Test-NetConnection <host> -Port 443      # TcpTestSucceeded : True
Test-NetConnection <host> -Port 8080     # TcpTestSucceeded : False
Invoke-RestMethod "https://<host>/api/update/check"   # returns JSON, current = v0.5.0
```
- [ ] **PASS:** 443 succeeds, 8080 fails, the API answers over HTTPS and reports `v0.5.0`.
- [ ] **FAIL:** if `start` fell back to HTTP or errored — that's amendment #7 (no silent fallback). Read the log; do not proceed.

- [ ] Dashboard renders over HTTPS.

- [ ] `$ExpectedHash` is a 64-char uppercase hex string.

- [ ] **PASS:** this matches `$ExpectedHash` in the downloaded script.
- [ ] **FAIL:** mismatch → the handler is hashing the wrong file or a stale copy. Fix C6 before proceeding.

## Step 3 — Run the bootstrap on a clean machine  *(the real test)*
On a **separate** box or a fresh VM (NOT the coordinator), in an **elevated Windows PowerShell 5.1** prompt. Copy the `bootstrap.ps1` over first.
```powershell
$PSVersionTable.PSEdition      # must read 'Desktop' (5.1). If 'Core', open powershell.exe instead.
powershell -ExecutionPolicy Bypass -File .\bootstrap.ps1
```
Watch the output for, in order:
- [ ] `C:\ArcVault-Agent\coordinator.crt` written (cert-first).
- [ ] `agent.exe` downloaded with no TLS error (5.1 pinning path).
- [ ] No "integrity check failed" throw → SHA-256 matched.
- [ ] `agent-config.yaml` written with `ca_cert_file` pointing at the crt.
- [ ] Service installed and started; recovery policy set.

Then confirm the service is actually up:
```powershell
sc.exe query arcvault-agent          # STATE : 4 RUNNING
Get-Content C:\ArcVault-Agent\logs\arcvault-agent.log -Tail 20
```
- [ ] **PASS:** service RUNNING, log shows a successful connection to the coordinator (not repeated TLS/401 failures).
- [ ] **FAIL — TLS error:** SAN/host mismatch — the `host` you set in `init` must match the URL the agent dials. Revisit Plan A SANs.
- [ ] **FAIL — 401:** the minted agent token isn't being accepted on `/downloads/agent.exe` or on register — recheck C5/C6 auth.
